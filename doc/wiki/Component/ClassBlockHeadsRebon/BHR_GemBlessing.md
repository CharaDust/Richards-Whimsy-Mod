# 宝石祝福（组件）
{`richards-whimsy-mod:gem_blessing`}
## 特点简介
一种负责控制工具对附魔的额外修饰的组件

## 构造
```
components（compound）
	richards-whimsy-mod:gem_blessing（compound）表示内含的宝石祝福
		Amethyst（boolean）表示是否具有紫锂辉祝福
		Sapphire（boolean）表示是否具有蓝宝石祝福
		Emerald（boolean）表示是否具有祖母绿祝福
		Ruby（boolean）表示是否具有红刚玉祝福
		Diamond（boolean）表示是否具有宝石钻石祝福
```
- 对于各个名词的解释：
	- 紫锂辉祝福：使得工具的【效率、横扫之刃、荆棘】魔咒视为等级+1的效果
	- 蓝宝石祝福：使得工具的【耐久、穿刺、水下呼吸】魔咒视为等级+1的效果
	- 祖母绿祝福：使得工具的【击退（冲击）、快速装填】魔咒视为等级+1的效果
	- 红刚玉祝福：使得工具的【时运（抢夺）、风爆】魔咒视为等级+2的效果
	- 宝石钻石祝福：使得工具的【锋利（力量）、保护】魔咒视为等级+2的效果

## 改写方法
- **等级增量不封顶**：直接在物品现有的附魔等级上加 +1 / +2，不检查该附魔自身的最高等级
  （耐久 3→4、时运 3→5、保护 4→6 都会真的超上限生效）。
- **按附魔判定，不按物品类型判定**：一条附魔只属于一种祝福，物品类型只决定「这个效果在原版里有没有用」
  （见备注里三叉戟 + 水下呼吸的例子）。
- **多种祝福可以共存**：5 个布尔值互相独立，一块物品带几种祝福就显示几行。
- **只认物品自己的 `ENCHANTMENTS`**：附魔书的 `STORED_ENCHANTMENTS` 不受影响。

## 实现（2026-10 落地）
| 位置 | 职责 |
| ---- | ---- |
| `component/ClassBlockHeadsRebon/BHR_GemBlessing` | 组件类型本体、5 个布尔值（`Blessing`）、祝福枚举与词条表、tooltip |
| `component/ClassBlockHeadsRebon/BHR_GemBlessingBonus` | 等级增量计算、附魔注册表缓存、折算「祝福生效后」的附魔组件值 |
| `mixin/ClassBlockHeadsRebon/BHR_GemBlessingEnchantmentMixin` | 三处注入：等级查询（加返回值）+ 两条 `runIterationOnItem`（重定向读组件那一次调用） |
| `item/ClassBlockHeadsRebon/BHR_GemBlessTest` | 施加途径（测试棒，见 [[BHR_GemBlessTest]]） |

- **虚化注入**，不写 `ENCHANTMENTS`：所以没附魔的工具加了祝福也不会亮附魔光效（备注第 3 条），
  铁砧 / 砂轮 / 附魔台看到的仍是真实附魔。
- **非破坏式**：两条 `runIterationOnItem` 不改原版方法体，只重定向它们「读 `ENCHANTMENTS` 组件」的那一次调用
  （2 参重载是 `getOrDefault`、4 参重载是 `get`）。原版的遍历、`matchingSlot` 槽位过滤、
  `EnchantedItemInUse` 构造全由原版执行，**其它模组注入在同一方法体里的逻辑照常生效**。
  早期版本的「`HEAD` 取消 + 复刻正文」已废弃 —— 那种写法会静默吞掉别人的注入。
- **4 参重载必须能返回非 null**：原版拿到 `null` 会跳过整段遍历，而「物品压根没有附魔组件」正是祝福的主场景。
- **兼容性口径**：`richards-whimsy-mod.mixins.json` 保留 `injectors.defaultRequire = 1`
  —— 与其它模组撞车时在加载期直接报错（响亮），便于后续在模组包里测兼容性，而不是静默失效。
- tooltip 由组件自己实现 `TooltipProvider`，经 Fabric 的
  `ItemComponentTooltipProviderRegistry.addAfter(DataComponents.ENCHANTMENTS, …)` 挂在原版附魔行之后；
  **原版附魔行显示原始等级**，祝福单独占一行。
- 关键前提：「物品上本来没有的附魔」也要算出等级，就需要动态附魔注册表的 `Holder`，
  因此缓存了一份 `HolderLookup`（服务端 `SERVER_STARTED` + 数据包重载、客户端换世界时刷新）。
  缓存在就绪前会降级为「只加成已存在的附魔」，不会崩。

## 备注
- **已实现**（2026-10）。验收口径（三叉戟只有耐久 1、加蓝宝石祝福）实测：
  `耐久 1 → 视为 2`、`无穿刺 → 视为 1`、`无水下呼吸 → 代码层视为 1、但主手槽位过滤后不生效`，
  清除祝福后回到 `耐久 1` 且只剩 1 条附魔。
- 当没有附魔工具被加上宝石祝福时，**不需要显示附魔光效**（虚化注入天然满足：不动 `ENCHANTMENTS`，
  `ItemStack#isFoil` → `isEnchanted` 只看真组件）。
- 组件字段名 `Amethyst` 保持原名（致敬《The Blockheads》），仅显示名改为「紫锂辉」。
- [[BHR_GemBlessing_1]] 的 NBT 实现已整体废弃，**不做存档迁移**（属于重置而非迁移）。
