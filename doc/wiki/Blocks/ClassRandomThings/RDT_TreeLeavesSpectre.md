# 通灵树叶（方块）
{`rdt_spectre_leaves`}
## 特点简介
一种半透明树木的树叶方块。玩家可以无窒息但稍有阻力地穿过；**顶面可以站立，按住 Shift 就能从顶面穿下去**
（与 [通灵原木](RDT_TreeLogSpectre.md)、[通灵木板](RDT_TreePlanksSpectre.md) 同一套碰撞逻辑，2026-10 统一）。

## 渲染
- 透明状态：依据纹理Alpha通道透明（`rdt/spectre_trsp_leaves.png` 整图 Alpha 只有 **0（42.19%）与 195（57.81%）** 两档 → 半透明档）
- 模型用 `block/cube_all`（六个面都带 `cullface`，所以「同类贴合面不渲染」能真正生效）
	- **刻意不用**原版 `block/leaves` 那张模型：它各面带 `tintindex: 0`（原版树叶靠生物群系上色），
		而通灵树叶是画好的淡蓝半透明图，**不参与染色** —— 用 `cube_all` 才不会给以后留一个「为什么会被染色」的疑问
	- 26.1 起**不再需要**手动注册渲染层（`BlockRenderLayerMap` 已删除），半透明档由贴图 Alpha 自动判定

## 改写方法
- **碰撞：顶面可站立 / 按住 Shift 穿过 / 侧面与身位在方块内可穿过（2026-10 起与木料同一套）**
	- **实现只有一份**：`RDT_SpectrePassThrough.collisionShape(pos, context, 父级形状)`，
		三块通灵木料都转发到它；本方块填的父级形状是 **`Shapes.empty()`**
		（父级是橡树树叶，而原版树叶的碰撞形状本来就是空的）
	- 这个参数只影响**非实体查询**（光照 / 支撑 / 渲染 / 红石 / 寻路），所以填空 = 树叶在这些方面
		保持原版行为；实体拿到的永远是「顶面整块 or 空」，于是多出了「站上去」这一条
	- 判定式照抄 26.2 的 `ScaffoldingBlock.getCollisionShape`；`Entity.isDescending()` 的实现就是
		`isShiftKeyDown()`，所以「按住 Shift」=「下降中」= 空碰撞 = 从顶面穿下去
	- ⚠️ **不要**顺手把父级形状也改成整块：那会让树叶的寻路 / 红石 / 支撑面偏离原版树叶
		（原版树叶在那些方面就是「空」）
- **位于方块内时减速（xyz 各乘 0.85）—— 已实现**：转发到 `RDT_SpectrePassThrough.dragInside`，
	与通灵原木 / 通灵木板同值 —— wiki 只写「稍有阻力」没给数，同一棵树的三块手感应当相同
- **透明状态 —— 不需要写**：透明档 26.1 起由贴图自动判定（见「渲染」）
- **环境光遮蔽 —— 不需要写**：本方块保持原版树叶的默认值（非实体兜底是空形状 → 默认给 1.0F），
	与通灵原木 / 木板那两块显式取 0.9F 的做法不同；**刻意如此**，免得改掉原版树冠的明暗关系
- 返回透明方块状态等其余「原版树叶自带」的行为，均由父级提供

## 事件
### 枯萎（原版的消失流程，获得随机刻时）
- 判定式与原版 `LeavesBlock` 完全一致（逐字节核验 26.2）：
	`DISTANCE == 7` 且 `PERSISTENT == false` → **掉落物品并原地移除**（`dropResources` + `removeBlock`）
- 「距离」是**图的连通距离**，不是欧氏距离：六个邻居里只要有**能阻断凋零的方块**，该方向取 0；
	其余取「邻居的距离 + 1」；本格取六向最小值
	- 于是砍掉树干后，树叶会一圈一圈（7 → 6 → … → 1）逐层传下去，最外层（`DISTANCE == 7`）先掉 —— 这就是原版的连锁枯萎
- **能阻断凋零的方块** = `#minecraft:prevents_nearby_leaf_decay`，原版把它定义成一条转发：`#minecraft:logs`
	- 26.2 的判定**不再直接读** `#minecraft:logs`，而是读这个新标签（26.2 新引入）
	- 原版方块进 `#minecraft:logs` 是数据包写死的，**模组方块必须自己进** —— 本模组已补
		`data/minecraft/tags/block/logs.json`，把 **通灵原木** 加进 `#minecraft:logs`（标签默认是并集，不写 `replace` 不会挤掉原版原木）
	- ⚠️ 这一条是**功能必需**，不是「获取方式」阶段的事：不加的话，树苗长出来的树叶算不出「旁边有树干」，
		距离全为 7 → 长出来的瞬间开始连锁枯萎，整棵树刚长出来就秃
- `PERSISTENT = true`（人为放置）的树叶既不参与距离传播、也不凋零 —— 机制与原版相同
### 含水（机制与原版相同）
- 本方块实现了原版的 `SimpleWaterloggedBlock`，因此**水流冲不掉它**：水流判定的第一道闸门是
	`Block instanceof LiquidBlockContainer`，命中它之后水走的是「把方块变成含水树叶」而不是「销毁方块」
- 这点与通灵原木 / 通灵木板**不同**：那两块不可含水，必须靠 `noCollision()` + `forceSolidOn()` 才挡得住水
	（见各自页面）。也正因如此，本方块**不能**加 `forceSolidOn()` —— 它会把「寻路可穿过」等手感一起改掉
### 飘落树叶粒子（26.2 新增，父级提供）
- 每次 `animateTick` 有 **1%** 几率在方块下方飘出一片淡白叶片（原版 26.2 给树叶新增的行为）
- 粒子取固定色（不随生物群系染色），与「不染色的淡蓝图」这个前提一致

## 方块状态
照抄原版树叶，共 **7 × 2 × 2 = 28** 个状态（与原版橡树树叶完全一致）
- DISTANCE（1~7）
	- 距离场，机制同上（`#minecraft:logs` → 0，否则邻居 +1，六向取最小）
	- 默认值 7；人为放置后会按周围方块重算
- PERSISTENT（布尔）
	- 人为放置时为 TRUE（持久，不参与距离传播也不凋零）；自然生成 / 种出来的为 FALSE
- WATERLOGGED（布尔）
	- 机制与原版相同

## 获取方式
### 战利品表
#### 采集
- 挖掘通灵树叶的合适工具是锄、剑和剪刀。
- 通灵树叶被剪刀或具有精准采集的工具挖掘破坏时，通灵树叶被破坏后会掉落自身。
- 现状：战利品表与挖掘工具标签（`mineable/hoe`、`sword_efficient` 等）按全项目既定决定**暂缓**，
	「获取方式」阶段统一落地。

## 备注
- ✅ 已实现（2026-10）：方块状态照抄原版、枯萎完全继承原版、可穿过且有阻力、顶面可站立、
	半透明走 `trsp` 贴图。实现位置
	`src/main/java/com/rcdmake/whimsy/block/ClassRandomThings/RDT_TreeLeavesSpectre.java`
- **2026-10 统一：碰撞逻辑收进了 `RDT_SpectrePassThrough`**（新增的共享实现类），
	本方块与通灵原木 / 通灵木板共用同一份判定式，差别只有「父级形状」与「要不要 `forceSolidOn`」两项。
	本方块的实际变化：原来形状恒为空，现在多出「顶面站得住 / 按住 Shift 从顶面穿下去」；
	**侧面与身位在方块内仍可穿过**（那两条分支没变）。
	实测（服务器端到端、在方块正上方放沙子看落点）：沙子停在树叶上方一格
	（`VERDICT_TOP_LEAVES_OK`），对照组（空气）的沙子一路掉到地面 —— 探针已删除。
- **为什么继承的不是 `LeavesBlock`**：26.2 的 `LeavesBlock` 是**抽象类**，多了两个抽象方法
	（`codec()` 与 `spawnFallingLeavesParticle(...)`，因为新增了飘落粒子）。本方块取原版现成的
	**不染色**子类 `UntintedParticleLeavesBlock`，把这两个抽象实现一起白拿 —— 这就是范式「继承**对的**父类」。
	（原版自己的 `oak_leaves` / `birch_leaves` 用的是会染色的 `TintedParticleLeavesBlock`，它们靠生物群系给叶子上色。）
- **引燃 / 烧毁为什么必须自己登记**：`ofFullCopy` 复制的是方块属性，火焰那张表是**另一套注册表**
	（Fabric 的 `FlammableBlockRegistry`），模组方块不在里面。值为 wiki 明文的 60 / 100。
- 地图颜色仍带星号（「待定，该方块为淡蓝色」）—— **未实现**，沿用父级。
- 与另外两块的对照（同一棵树，但机制不同，别互相照抄）：
	| 项目 | 通灵原木 / 通灵木板 | 通灵树叶 |
	| --- | --- | --- |
	| 碰撞 | 顶面可站立、按住 Shift 穿过（**共用同一份实现**，差别只有父级形状） | 同左（父级形状填「空」） |
	| 父级形状（非实体兜底） | 整块 | 空（原版树叶本来就是空） |
	| 挡水手段 | `noCollision()` + `forceSolidOn()`（不可含水） | 靠 `SimpleWaterloggedBlock`（原版同款）；**不能**加 `forceSolidOn` |
	| 环境光遮蔽 | 显式 0.9F | 保持原版默认（刻意不改） |
	| 方块状态 | AXIS / 无（木板） | DISTANCE / PERSISTENT / WATERLOGGED |
