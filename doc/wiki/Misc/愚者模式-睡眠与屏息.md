# 愚者模式：睡眠、屏息与观察世界

> 版本：Minecraft 26.2 / Fabric。本文记录机制设计、26.2 的相关实现位置，以及实机踩过的坑。
> 代码入口：[`BHR_Sleep`](../../../src/main/java/com/rcdmake/whimsy/misc/ClassBlockHeadsRebon/BHR_Sleep.java)、
> [`BHR_Energy`](../../../src/main/java/com/rcdmake/whimsy/misc/ClassBlockHeadsRebon/BHR_Energy.java)、

## 1. 一句话总览

愚者模式的睡觉**不跳过时间**，而是把<b>世界时钟</b>加速 20 倍；精力按<b>世界 tick</b> 结算，睡满给黄条并自动起床。
睡觉时还能「观察世界」——纯客户端的灵魂出窍，相机脱离身体四处看，状态栏照常显示。

---

## 2. 26.2 的睡眠链路（改动点都在这条链上）

| 环节 | 位置 | 说明 |
|---|---|---|
| 右键床 | `BedBlock#useWithoutItem` | 先读 `EnvironmentAttributes.BED_RULE`：`explodes` 为真就炸床并 return，**根本进不了睡觉** |
| 入睡 | `ServerPlayer#startSleepInBed` | 原版会判 `BED_RULE.canSleep`（overworld 是 `when_dark`）、`canSetSpawn`（会给床边钉重生点）、距离、阻挡、附近怪物 |
| 睡眠中每 tick | `Player#tick` | `sleepCounter++`（上限 100）；**每 tick 复查 `canSleep`，不满足就叫醒** |
| 睡够 | `Player#isSleepingLongEnough` | `sleepCounter >= 100`（5 秒） |
| 床存在性 | `LivingEntity#tick` | `isSleeping() && !checkBedExists()` → 叫醒；`checkBedExists` = 「睡的那格必须是 `BedBlock`」 |
| 跳夜 | `ServerLevel#tick` | `areEnoughSleeping && areEnoughDeepSleeping` → `moveToTimeMarker(WAKE_UP_FROM_SLEEP)` + `wakeUpAllPlayers()` |
| 比例统计 | `SleepStatus#update` | 只滤旁观者，**会把愚者算进去** |
| 时间推进 | `ServerClockManager` | 昼夜是 `totalTicks`，每 tick `+= floor(partialTick + rate)`；`rate` 由 `/time rate` 设置（1e-5 ~ 1000） |

### 本模组在链条上的接管

| 目标 | 做法 |
|---|---|
| 愚者不算进原版比例 | `BHR_SleepStatusMixin` 把愚者从 `SleepStatus` 的分子与分母里剔掉 |
| 跳夜只叫醒非愚者 | `BHR_ServerLevelSleepMixin` 接管 `wakeUpAllPlayers`，并按 Δ 世界 tick 给睡着的愚者记账 |
| 任意时刻都能睡、床不设重生点 | `BHR_ServerPlayerSleepMixin` 直接接管愚者的 `startSleepInBed` 入口 |
| 睡着不被「床位规则」弹起来 | `BHR_PlayerSleepMixin` 把 `Player#tick` 里的 `canSleep` 判定对愚者短路 |
| 席地而睡不被「床不存在」弹起来 | `BHR_FloorSleepMixin` 对席地睡眠者把 `checkBedExists()` 短路（否则 20 Hz 睡/醒抖动） |

## 3. 比例：分组分母

```
G_fool = 该维度内、非旁观、gameMode == FOOL 的玩家
G_van  = 该维度内、非旁观、其它模式的玩家

need_fool = max(1, ceil(|G_fool| * pct / 100))
need_van  = max(1, ceil(|G_van|  * pct / 100))
```

- **分母按组、按维度**：`pct = 100` 时两组互不干扰，不会互相锁死；
- 原版跳夜看 `need_van`，愚者加速看 `need_fool`；
- 两边都要求**睡够 100 tick**（5 秒），不是「躺下就算」。

### 五个判定实例（pct 40、5 愚 + 5 生，need 各为 2）

| 场景 | 结果 |
|---|---|
| 5 生存全睡 | 跳夜；愚者不加速 |
| 5 生存 + 1 愚者睡 | 跳夜；愚者 1 < 2 不加速；按 Δ 记账（通常补不满 → 继续睡） |
| 1 生存 + 5 愚者睡 | **不跳夜**；加速，随补满逐个醒，降到 1 人才停 |
| 10 人全睡 | 先跳夜（只叫醒生存），剩余愚者 ≥ 2 就继续 20× 直到补满 |
| 换维度 | 两组各自按维度缩小分母 |

## 4. 时间加速

- 愚者深睡人数达标 → `ServerClockManager.setRate(clock, 20.0F)`；
- 不达标 → 恢复**接管前的速率**（不是硬写 1.0：接管时用前几 tick 观测到的自然速率兜底）；
- 只在**有 `default_clock` 且非固定时间**的维度生效（下界没有时钟，末地是固定时间）；
- 音效：进入加速播 `bhr_speedup`，退出播 `bhr_slowdown`，同维度 2 秒防抖。

> 为什么不用「跳 tick」实现：26.x 的昼夜已经和游戏刻解耦，改 `rate` 即可，
> **MSPT 零成本**，也不会跳过任何 tick 类机制。

## 5. 睡眠补充与床档

精力**按世界 tick 结算**：世界每走 1 tick，睡着的愚者 +`perWorldTick` 点。20× 加速时折合 20 倍/游戏 tick。

| 床档 | perWorldTick | 20× 下折算 | 补满耗时（从 0） | 睡满奖励 | 箭头 |
|---|---|---|---|---|---|
| 席地 / 强制睡眠 | 1 | 20 / 游戏tick | 50 s | 无 | 2 |
| 木板床（`bhr_wooden_bed`） | 1.5 | 30 | 33 s | 120 s = **2400** 点 | 3 |
| 软床 / 原版床 | 2 | 40 | 25 s | 300 s = **6000** 点 | 4 |
| 金床（未落地） | 10 | 200 | 5 s | 1000 s = **20000** 点 | 5 |

- 床档判定走方块标签：`richards-whimsy-mod:fool_bed_wooden` / `...:fool_bed_gold`，原版床自动归「软床」；
- **入睡门槛**：主条 > 16000 拒绝入睡（提示「你还不够累」），顺便消灭了「进床时已满」的边界；
- **补满即醒**，并按床档发黄条（`bhr_barr_super_energy`，上限与主条同为 20000）；
- 睡眠期间**暂停基础消耗**；黄条**先于主条消耗**，所以主条归零必然意味着两条皆空；
- 主条 0 且站在地面 → **强制睡眠**（原地躺下、不给奖励、不给黄条，但**计入愚者比例**）。

---

## 6. 跳夜平账

非愚者满足比例时照原版跳夜，但：

1. 时钟照常 `moveToTimeMarker`；
2. **只叫醒非愚者**；
3. 睡够 100 tick 的愚者按 Δ 世界 tick × 1 点记账；满了就强制醒，没满继续睡。

## 7. 屏息与射弹精度

- **触发**：潜行 + 正在拉弓 / 蓄力三叉戟（**弩不算**，它是待激发）；
- 氧气按**绝对值记账**扣 3 点/游戏 tick（不能靠「-3」硬减，原版回氧会把它吃掉）；
- 氧气见底：**不窒息**，只取消屏息，并锁存 `breath_blocked`，必须松开潜行再按才能重进；
- 屏息满 2 秒（40 tick）后，射出的箭 / 三叉戟**散布归零**。

### 散布是怎么来的

26.2 的射弹散布只有一处 —— `Projectile#getMovementToShoot`：

```java
new Vec3(xd, yd, zd).normalize()
   .add(random.triangle(0, 0.0172275 * uncertainty),   // x
        random.triangle(0, 0.0172275 * uncertainty),   // y
        random.triangle(0, 0.0172275 * uncertainty))  // z
   .scale(pow);
```

- **是射弹自己抽的随机数**，与玩家移动无关（原版弓没有移动散布惩罚）；
- 弓的 `uncertainty = 1.0`（**满蓄力也是 1.0**，满蓄力只影响 `pow` 与暴击）；
- 三叉戟同样 `1.0`；
- 把它压成 0，方向就只由朝角决定，轨迹是确定的抛物线（仍受重力与阻力影响）。

实现：`BowItem#shootProjectile` 与 `TridentItem#releaseUsing` 各一处 `@Redirect`，屏息够 2 秒时传 0。

## 8. 观察世界（灵魂出窍）

### 形态

- **纯客户端**：本地 `new Marker(...)` 当相机实体（无渲染、无 AI、**不进实体表、不发包**），
  `Minecraft#setCameraEntity` 切过去；退出时换回玩家并 `discard()`；
- 相机只读坐标/朝向，**不入实体表** —— 本地实体 id 是 0，`ClientLevel#addEntity` 会抛
  `IllegalStateException: Tried to access entity ID before ID assignment`，所以补一个负数 id 兜底；
- 移动：读原始按键（WASD / 空格 / 潜行），10.9 格/秒 + 惯性收敛；鼠标转向由 `MouseHandler#turnPlayer` 的
  `@Redirect` 交给相机，**身体不转、不发转向包**；
- 边界：只在客户端已加载区块内看（不做服务端推流）。

### 入口与命令栏

出窍的入口只有一个：**床上界面**（睡觉时按 T 打开）里的「观察世界」按钮。进入时动作栏会提示
「按数字键打开菜单」。

出窍期间 1~9 号快捷栏键被**命令栏**接管（和旁观者模式一样，不切换手上的物品）。命令栏
**整套复用原版** `SpectatorGui` + `SpectatorMenu`：底部升起的快捷栏、选中高亮、按键号角标、
动作名、5 秒后淡出，以及「先选中、再按一次才执行」的两段式交互，全部是原版行为；
我们只替换菜单里的条目（`SpectatorMenuCategory`，由 `BHR_SpectatorMenuMixin` 在
`SpectatorMenu` 构造完成时换进去）。

| 键 | 条目 | 图标 |
|---|---|---|
| 1 | 传送到玩家（子菜单，列出其他在线玩家） | 原版 `spectator/teleport_to_player` |
| 2 | 传送到队伍成员（子菜单，按记分板队伍过滤） | 原版 `spectator/teleport_to_team` |
| 3 | 返回身体 | 当前所睡那张床的物品；席地而睡 / 强制睡眠 → 石头 |
| 4 | 起床 | 时钟 |
| 9 | 关闭菜单 | 原版 `CloseSpectatorItem`（第 8 格，位置不动） |

- **1/2 只移动相机**，本体仍然躺在床上 —— 这是和原版旁观者传送最大的区别；
  瞬移时把「上一 tick 位置」一起对齐，避免镜头拖出一条长位移轨迹；
- 按键由 `Minecraft#handleKeybinds` 的 HEAD 先于原版 `consumeClick()` 消费，所以不会漏到
  快捷栏逻辑；菜单未开时连调两次 `onHotbarSelected`，把原版「先开菜单」那一步省掉，
  做到「按一次点亮、再按一次执行」。
- 普通快捷栏在出窍时**不画**（`extractItemHotbar` 取消），由命令栏取代。

### 出窍期间要压掉的原版行为

| 现象 | 原因 | 处理 |
|---|---|---|
| 床界面一关就被顶回来 | `Gui#tick`：只要在睡且没界面就自动开 `InBedChatScreen` | 出窍时把该处 `isSleeping()` 判定短路 |
| 关界面 = 起床 | `InBedChatScreen#onClose` 会发 `STOP_SLEEPING` | 出窍期间关闭该界面一律跳过唤醒 |
| 全屏睡梦黑幕 | `Hud#extractSleepOverlay` 按 `sleepTimer` 画全屏黑，画在 HUD 之后 | 出窍时整段跳过 |
| 只剩经验条 | `Hud#extractPlayerHealth` 用 `getCameraPlayer()` 取玩家，相机是 Marker 时返回 null，护甲/生命/饥饿与自定义资源条**整段被跳过** | 出窍时让它返回真实玩家 |
| 按 F1 后 HUD 全没 | `Hud#isHidden` | 出窍期间临时压成 false，提取完还原 |
| 镜头在两个地点间高频闪 | 相机每帧用 `lerp(partialTicks, xo, x)`；本地实体不 tick，`xo/yo/zo` 永远停在 0 | 每 tick 开头手动同步旧值 |
| 移动一顿一顿 | 移动完再同步旧值，插值两端相等 = 不插值 | 旧值在移动**前**记，移动后交给插值 |

## 9. 其他数值

- 精力 < **4000**：每 5 秒续一次原版**黑暗**（10 秒，同源只刷新不叠加）；
- 精力消耗：基础 1 / 游戏 tick；**非主世界减半**；瞄准中（弓 / 弩 / 三叉戟）+2；
- 精力箭头：醒着 2 个、异维度 1 个、瞄准 +1 个；睡着按床档 2~5 个，**入梦头 5 秒不显示箭头也不补充**。

## 10. 世界进程加速（5×）

只在加速生效时、对睡着愚者周围 5×5 区块：

- **随机刻**：多跑 4 遍 `ServerLevel#tickChunk`（作物、草、雪、冰、树叶、火）；
- **方块实体白名单**：熔炉系、营火多调 4 次 ticker —— 26.2 的方块实体没有 `tick()` 方法，
  要走 `BlockState#getTicker(...)` 拿到 ticker 再调用。

刻意不动：红石元件、漏斗、刷怪笼、酿造台，以及所有第三方 mod（含本模组其它模块）的方块实体。

## 11. 实机踩过的坑（改这块代码前请先看）

1. **Mixin 回调参数必须是目标参数的前缀**。`Hud#extractRenderState(GuiGraphicsExtractor, DeltaTracker)`
   的回调只写 `(DeltaTracker, CallbackInfo)` 会让**整个 mixin 类应用失败**（而不是只挂一处），
   表现为「改了完全没反应」。日志里搜 `Mixin apply ... failed`。
2. **26.2 的点击 API**：`mouseClicked(MouseButtonEvent, boolean)`、`Button#onPress(InputWithModifiers)`，
   老签名会在运行时抛 `Invalid descriptor`。
3. **`@Shadow` 只能指向目标类自己声明的成员**：`addRenderableWidget` 声明在 `Screen` 上，
   在 `AbstractContainerScreen` 的 mixin 里影子不到，要对 `Screen` 开 `@Invoker`。
4. **睡眠状态的判定**：`LivingEntity#isSleeping` 只看 `SLEEPING_POS_ID` 是否为空；
   但「床存在」另有一道 `checkBedExists`，席地而睡必须绕过它。
5. **发 `STOP_SLEEPING` 的地方只有两处**：原版床上界面的「离开床」按钮与 `onClose`。
   排查「睡着被叫醒」时直接打调用栈最快。
