# 客户端渲染接线（misc）

> 本页收录纯客户端的渲染层与颜色接线，供重制时对照。

## 渲染层注册
| 模块 | 方块 | 渲染层 |
| --- | --- | --- |
| BHR | 紫锂辉、蓝宝石、祖母绿、红刚玉、宝石钻石 | 半透明 |
| DEV | 幽灵方块 | 半透明 |
| RDT | 青金石玻璃、石英玻璃、糖玻璃、垫脚方块 | 镂空 |
| RDT | 通灵原木 | 半透明 |
| WI | 气凝胶、固化水方块 | 半透明 |

## 颜色提供器
| 目标 | 说明 |
| --- | --- |
| 固化水方块（方块颜色） | 取所在生物群系的水颜色 |
| 固化水方块（物品颜色） | 当前返回固定的洋红色（占位实现）→ **重制后改为专用物品贴图**（见下） |

## 现状与限制
- 渲染层为**手动逐块注册**；漏注册会导致方块渲染异常
- 颜色提供器中的物品颜色是写死的占位值，与方块颜色不一致

## 重制注意
- 26.x 已**删除**手动渲染层注册：透明/镂空改由贴图像素自动判定（含半透明像素 → 半透明；仅全实心+全透明 → 镂空）。因此上表的渲染层注册**应整体删除**，只需保证贴图通道正确
- 方块颜色注册方式已改为 `BlockColorRegistry`，颜色提供器需重写
- 固化水方块的“与原版水同原理的后期上色”尚未实现，重制时可一并评估

## 重制结果（26.2）
- **渲染层**：上表整块作废，无需任何代码；只靠贴图 Alpha 自动判定——
  `wi/aerogel.png`（Alpha 恒 32）与 `wi/static_liquid_water.png`（Alpha 180）→ 半透明；
  `wi/glass_sugar.png`（仅 0 / 255 两档）→ 镂空。
  RDT 同批：`rdt/glass_lapis.png`、`rdt/glass_quartz.png`、`rdt/step_block.png` → 镂空；
  `rdt/spectre_trsp_log_{side,end}.png` → 半透明（整图 Alpha 恒 195）。
- **⭐「站在/穿过可穿过方块时满屏一张方块贴图」= 原版「方块屏幕效果」，开关是 `isViewBlocking(Blocks::never)`**
  （2026-10 定位并修复，通灵原木）：
  <pre>
  症状   站着（尤其潜行）时视线被一张方块贴图盖满，不是网格里的面片、不是雾
  真凶   ScreenEffectRenderer.getViewBlockingState(player)
           → 绕着眼睛取 8 个采样点，任一点所在方块满足
             (state.getRenderShape() != RenderShape.INVISIBLE && state.isViewBlocking(level, pos))
           → 返回该方块状态
         ScreenEffectRenderer.submitBlockSprite()
           → blockStateModelSet.getParticleMaterial(state).sprite()   // 方块粒子贴图
           → 提交一个屏幕空间四边形（-1,-1 → 1,1，即铺满整屏）
  修法   属性工厂里加 .isViewBlocking(Blocks::never) → 上面第一个条件不成立 → 覆盖层整个不提交
  </pre>
  ⚠️ **别去查区块网格那条路**：面片在 section mesh 编译期就烘好了（`SectionCompiler` →
  `ModelBlockRenderer.tesselateBlock`），编译后在 `SectionRenderDispatcher` 里只按
  `TranslucencyPointOfView` 重排，压根不回查相机位置 —— 所以「按相机跳过面片」不可靠，而这个问题也根本不在那条路径上。
  - `BlockModelLighter`（环境光遮蔽角点）也读 `isViewBlocking`，所以加这一行会顺带影响平滑光照，
    对「本来就不遮挡的方块」是符合直觉的方向；`noOcclusion()` 才是控制方块之间面剔除的那个。
  - `DEV_GhostBlock` 早就写了这一行 —— 幽灵方块当初没这个症状，就是因为它写了。
- **「实体能穿过但不会被水冲掉」的正确配方**（RDT 青金石/石英玻璃、通灵原木、DEV 幽灵方块都涉及，本项目为此花过大量时间）：
  <pre>
  实体能否穿过      ← getCollisionShape（空形状 = 穿过）—— 但这只是「形状」这一半
  「概念性固体」    ← BlockStateBase.calculateSolid()，26.2 里它按**顺序**读：
                      forceSolidOn → true；forceSolidOff → false；dynamicShape（无形状缓存）→ false；
                      缓存下来的 collisionShape 为空 → false；否则看形状大小
  「水能不能占」    ← FlowingFluid.canHoldAnyFluid：if (!state.blocksMotion()) return true;   ← 可占 → 方块被冲掉
  「水能不能穿墙」  ← FlowingFluid.canPassThroughWall：也读**2 参 getCollisionShape**（= CollisionContext.empty()）
  </pre>
  ⚠️ **关键坑**：`legacySolid` **不是**只看 `Properties` 开关 —— 它会把「状态创建时缓存的碰撞形状」算进去。
  而 `BlockStateBase.getCollisionShape(level, pos)` 这个 2 参重载传的是 `CollisionContext.empty()`（**没有实体**）。
  所以凡是按实体区分碰撞的方块，**兜底分支绝不能返回空形状**，否则：
  1. `legacySolid` 被判为 false → 水流直接占据、方块被冲掉（青金石玻璃踩的就是这个）；
  2. `canPassThroughWall` 也拦不住水；
  3. 告示牌之类靠非实体上下文的支撑判定全部失败。
  - **碰撞按实体区分**（青金石/石英玻璃）：保留碰撞开关、只覆写 `getCollisionShape`，
    **兜底返回 `super.getCollisionShape(...)`（父级形状）**；想更稳可以再加 `forceSolidOn()`。
  - **碰撞恒为「无」**（幽灵方块；通灵原木 2026-10 前是这一类）：`noCollision()` + `forceSolidOn()` —— 只写前者会被水冲掉。
  - **碰撞按情境给形状**（通灵原木，2026-10 起）：覆写 `getCollisionShape`，按「顶面可站 / Shift 穿过」给出形状
    （判定式与 26.2 的 `ScaffoldingBlock` 相同），属性层**保留** `noCollision() + forceSolidOn()`。
    形状换来换去都不会把水引回来 —— 水流那道闸门读的是 `legacySolid`，而它被 `forceSolidOn()` 钉死了。
  - 两种情况都建议再补 `canBeReplaced(state, fluid) = false` 当第二道保险。
- **方块颜色**：已用 `BlockColorRegistry` + 原版现成的 `BlockTintSources.water()` 重写
  （与流体水同一套生物群系水色），接线在 `RichardsWhimsyModClient`。
- **「同类贴合面不可见」的两个前提**（踩过一次，记下来）：
  1. 方块类覆写 `skipRendering`（同类邻居 → true）；
  2. **模型里那一面必须写 `cullface`**。按面方向分组用的是 `cullface`，没写 `cullface` 的面会落进
     「无方向」组，渲染时压根不问 `shouldRenderFace`，贴合面会一直被画出来。
     原版 `block/cube.json` 六个面都带 `cullface`（`cube_all` 继承它，所以直接用 `cube_all` 的方块天生满足）；
     而为了加 `tintindex` 手写 `elements` 的模型（如 `wi_static_liquid_water.json`）**必须自己补上 `cullface`**
     —— `tintindex` 与 `cullface` 可以同面共存（原版 `grass_block.json`、`leaves.json` 即是）。
- **物品颜色**：洋红占位值**不再使用**。方块物品改用专用贴图
  `wi/static_liquid_water_mapped.png`（已把水色乘进灰度图）——
  物品与方块贴图不同，因此两者模型不同：
  方块 = `models/block/wi_static_liquid_water.json`（灰度 + tintindex + cullface），
  物品 = `models/item/wi_static_liquid_water.json`（mapped 贴图，无 tintindex）。
  26.2 的物品模型定义（`assets/<ns>/items/<id>.json`）由 datagen 的
  `ItemModelGenerator` 产出，其中的「物品模型例外表」把这两个方块物品指向各自的 `item/` 模型。
