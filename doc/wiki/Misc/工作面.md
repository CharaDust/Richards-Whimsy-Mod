# 工作面（Working Surface）

> 目录：`com.rcdmake.whimsy.surface`（服务端/公共）+ `com.rcdmake.whimsy.client.surface`（客户端）
> 状态：**2026-12 新增**。把原先「制作台 / 简易篝火」两份几乎一样的实现合并成一套内核。
> 术语：The Blockheads 的 wiki 把所有「能拿材料换产物的方块」统称 **Working Surface**，本项目中译为 **工作面**。
> 各台自己的名字保持不变：**制作台**（`bhr_workbench`）、**木工台**（`bhr_woodwork_bench`）、**简易篝火**（`bhr_campfire`）。

## 基本

工作面的公共逻辑（等级、配方选择、进度、燃料、存档、菜单、界面、网络）全在这一层；
每一台只在**一份规格**里声明差异：

| 字段 | 含义 | 制作台 | 木工台 | 简易篝火 |
| --- | --- | --- | --- | --- |
| `id` | 注册名 / 配方目录名 / 菜单注册名 | `bhr_workbench` | `bhr_woodwork_bench` | `bhr_campfire` |
| `guiTexture` | 界面底图（相对 `assets/richards-whimsy-mod/`） | `workbench` | `workbench` | `fuel_workbench` |
| `levelMax` | 等级上限（下限恒为 1） | 29 | 3 | 2 |
| `fuelSlots` | 燃料档位数，0 = 不烧燃料 | 0 | 0 | 3 |
| `fuelUnitTicks` / `fuelMaxTicks` | 单位燃烧时长 / 燃料槽上限 | — | — | 300 / 3000 |
| `panelShift` | 需求格 / 水晶 / 结果 / 倍率的整体 x 偏移 | 0 | 0 | 18 |

## 文件分工

| 文件 | 职责 |
| --- | --- |
| `WorkingSurfaceSpec` | 上面那张表的载体；另有 `titleFor(level)`（**标题一律带等级**） |
| `WorkingSurfaceBlock` | 等级方块状态、放置取等级、掉落带等级、右键开界面 |
| `WorkingSurfaceEntity` | 配方选择、倍率、进度、燃料、结果栏、暂存原料、存档 |
| `WorkingSurfaceMenu` | 槽位下标由 spec 推导（有无燃料列、面板偏移） |
| `WorkingSurfaceScreen` | 一份绘制覆盖三台（底图 / 偏移 / 燃料列 / 滚轮） |
| `FuelOption` | 一档燃料（显式候选 + 可选标签兜底） |
| `WorkingSurfaceStateSync` | 方块外观钩子（篝火用它刷 `lit`） |
| `VanillaRecipeProjector` / `VanillaRecipeIndex` / `SurfaceRecipesPayload` / `SurfaceNetwork` | 原版配方投影与下发，见下 |

## 进度模型：时间差 + 区间结算

进度**不是**逐 tick 累加的，而是现算：

```
虚拟时间 = (暂停中 ? 暂停起点 : min(now, 燃料燃尽刻)) − 累计暂停
进度     = clamp(虚拟时间 − 本份开始刻, 0, 本份时长)
```

- 没有界面在看时方块**完全不 tick**，区块卸载也不会让进度变慢；重新打开界面按差额一次补齐；
- 燃料台的「缺燃料暂停」用**区间**表达（记下这批燃料烧到哪一刻），补燃料时把那段区间一次性累加进累计暂停——
  所以燃料台也**不需要每 tick 干活**；
- 唯一的周期心跳是**随机刻**（仅篝火）：结算区间 + 把 `lit` 状态跟上，一次只做几次整数比较；
- 升级配方**不烧燃料**（它改的是方块自己的等级）。

## 配方来源（两条）

| 来源 | 位置 | 谁读 |
| --- | --- | --- |
| 模组自带（愚者配方） | jar 内 `data/richards-whimsy-mod/bhr_recipe/<工作面>/**.json` | 两端各读一份 |
| 原版 / 数据包配方 | 服务端扫 `data/*/recipe/**.json` → 过滤 → 翻成愚者配方 JSON → 随开界面下发 | 服务端投影，客户端接收 |

两端注入到同一张表后，「选配方 / 看成本 / 开始制作 / 专家回退 / 等级闸门」全部复用同一套代码，
远端配方的 id 形如 `richards-whimsy-mod:vanilla/<工作面>/<序号>`，与本地配方不冲突。

### 原版配方投影

- **为什么必须下发**：26.2 客户端的 `RecipeAccess` 只剩 `propertySet(...)` 与 `stonecutterRecipes()`，
  客户端拿不到通用配方表。「双端都装模组」并不能变出配方表，只是省掉了降级路径。
- **为什么读数据包 JSON 而不是 `RecipeManager`**：26.2 的 `Recipe` 已经没有 `getIngredients()`，
  原料改由 `RecipeDisplay` / `SlotDisplay` 表达；而数据包 JSON 里 `pattern` / `key` / `ingredients` 是一等公民，
  读它既直白又天然跟着 `/reload` 走。
- **过滤规则**（`data/richards-whimsy-mod/surface/vanilla_recipes.json`，数据驱动）：
  1. 只收 `crafting_shaped` / `crafting_shapeless`；
  2. 产物命中产物白名单里的某个 tag；
  3. 每个材料命中材料白名单：材料是物品 → 该物品在某白名单 tag 里，或本身被直接写进白名单（如 `minecraft:stick`）；
     材料是标签 → 该标签本身在白名单里。
- **等级与耗时**：原版配方没有这两个字段，由规则表给（木工台 = **L2 / 5 秒**）。
- **校验**：服务端启动时会打印 `[vanilla] <工作面> 投影出 N 条原版配方`；DEBUG 日志里逐条列出翻好的 JSON。
- **失效**：`/reload` 后服务端清缓存（`ServerLifecycleEvents.END_DATA_PACK_RELOAD`），
  客户端在**下一次打开界面**时拿到新的一份。

## 产物族（family）

把「原版按树种拆开的一堆配方」压成一条的机制，用于**本地**配方：

```json
{ "result": { "family": "door", "from": 0 } }
```

配套 `data/richards-whimsy-mod/bhr_family/<族名>.json`：

```json
{ "source_suffix": "_planks", "target_suffix": "_door", "default": "minecraft:oak_door" }
```

解析顺序 `map` → 换后缀查注册表 → `special` → `default`，所以 `oak_planks → oak_door`、
`bhr_fruit_planks → bhr_fruit_door` 全部自动成立，以后加树种只要命名守约就一行都不用改。
`from` 指定「哪一格需求决定产物」，取的是**实际投进方块的那个物品**。

## 配方栏交互

- 8 格配方栏 + 滑块；**鼠标停在配方栏上滚动滚轮可逐条上/下翻**（不加文字提示，通用直觉）；
- 拖动滑块适合大跨度；滚轮连发时以本地「待确认偏移」为准，等服务端同步追平后自动清掉；
- 缺料 / 等级不足的配方会盖纱显示，等级不足的现在**也会拦住「开始制作」**（早期只有红纱、不拦）。

## 存档键

`recipe`（配方 id，权威）/ `batches` / `craft_start` / `total` / `scroll` / `remaining` /
`preferred` / `pending` / `paused_ticks` / `pause_start` / `fuel_end` / `fuel_stored` / `fuel_pref`。
老存档可直接读（键名沿用制作台时期的）。

## 新增一台工作面

1. 写一个继承 `WorkingSurfaceBlock` 的方块类，给出 `SPEC`（构造器里 `super(properties, SPEC)`）；
2. `OnInit()` 里按序注册：方块 → 带等级组件的方块物品 → `WorkingSurfaceEntity.registerType(...)` →
   `WorkingSurfaceMenu.register(SPEC)`；
3. 主类 `onInitialize()` 调它；客户端把 `WorkingSurfaceScreen` 接到该菜单类型（见 `RichardsWhimsyModClient`）；
4. 建配方目录 `bhr_recipe/<id>/`；
5. 若要订阅原版配方，在 `surface/vanilla_recipes.json` 里加一段规则，并在 `SurfaceNetwork` 的发送路径里自动生效。

## 已知限制

- `/reload` 后**正开着的**工作面界面不会自动刷新，需关闭重开；
- 愚者配方 / 原版投影配方都不是原版 `Recipe`，**JEI 看不到**它们（JEI 适配待做，接入方式是 `jei_mod_plugin` 读本模组数据，不需要网络）；
- 原版投影一次全量下发（木工台 81 条、约几十 KB）；以后出现订阅上千条配方的工作面时再加分页。
