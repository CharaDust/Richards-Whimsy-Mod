## 1. 核心判断

### 1.1 这不是一次升级，而是四次升级的叠加

从 1.20.4（2023-12）到 26.2（2026-06-16，代号 "Chaos Cubed" ✅）横跨约 2 年半、十多个大版本。26.1 被 Fabric 官方称为 *"the largest [changes] we have ever made for a single release"*（[Fabric for Minecraft 26.1](https://fabricmc.net/2026/03/14/261.html) ✅）。

对本项目而言有四道结构性断层，任何一道单独出现都足以让"改个版本号再编译"失效：

| 断层 | 版本 | 本质 | 影响面 |
| --- | --- | --- | --- |
| **A. 反混淆 + 映射体系切换** | 26.1 | Minecraft 不再混淆；**Yarn 停止官方支持**；没有 `mappings` 配置；Loom 换成不做 remap 的新插件 | **全部 90 个 Java 文件**、构建脚本、CI、Mixin 目标描述符 |
| **B. 物品组件化** | 1.20.5 | 物品 NBT → `DataComponentPatch`；`FoodComponent`→`FoodProperties`；`FabricItemSettings` 移除 | 物品类、NBT 玩法（`BHR_GemBlessing*`）、物品栏 |
| **C. 注册/数据驱动重构** | 1.21 ~ 1.21.5 | 附魔/药水注册表化、`HolderSet` 过渡、数据包目录单数化、硬编码物品子类（`SwordItem` 等）移除改数据组件 | 81 处 `Registry.register`、4 个数据包目录、数据生成器 |
| **D. 渲染管线重写** | 1.21.5 → 26.2 | `RenderType` 体系重构、自动 `ChunkSectionLayer`、`MultiBufferSource` 移除、26.2 Vulkan 后端 + Feature Rendering 接管 | `function/ClassDEV/Render/**`、`**/RenderType/*`、`screen/**`、后处理着色器 |

### 1.2 必须接受的两个硬事实

1. Fabric 官方明确：**1.21.11 及之前的模组，不经至少重新编译无法在 26.1+ 工作**（✅ [26.1 博客](https://fabricmc.net/2026/03/14/261.html)：*"no mods from 1.21.11 or before will work without, at a minimum, recompilation"*）。
2. **Yarn 已不再被 Fabric 官方支持**，且 **26.2 根本没有 Yarn 映射**：
   - ✅ `https://meta.fabricmc.net/v2/versions/yarn/26.2` 返回 `[]`（`/26.1` 同样为空，`/1.21.1` 正常）
   - ✅ 官方示例模组 `26.2` 分支的 `gradle.properties` **没有 `yarn_mappings`**，`build.gradle` **没有 `mappings` 行**

### 1.3 好消息

本项目只有约 4,598 行 Java、90 个文件，架构扁平、注册样板高度重复（见 [01 §3.2](./01-环境勘察报告.md)）。而且**映射迁移是可自动化的**（见 §4.2），属于"批量改写 + 逐处复核"的工程，而非架构重写。

## 3. 破坏性变更清单（按本项目实际用到的 API 组织）

### 3.1 断层 A：映射体系切换（26.1）——**本次升级最大的单项工作**

因为 26.1+ 已去混淆，"改名"= **Yarn → 官方名**，是全代码库级别的重命名，不是几处 API 调整。

#### 3.1.1 最重要的更正：`Identifier` 仍然是 `Identifier`

- Yarn `net.minecraft.util.Identifier` → 官方 **`net.minecraft.resources.Identifier`**：**简单名不变，只换包**。
- ✅ 核验方式：Fabric API `0.161.0+26.2` 中有 **346** 个 class 文件引用 `net/minecraft/resources/Identifier`，引用 `net/minecraft/resources/ResourceLocation` 的是 **0** 个（`0.161.0+26.3` 同样是 349 : 0）。
- → **常见误解**："官方名是 `ResourceLocation`"。**在 Fabric 26.2 生态里不是**。
- 工厂方法：1.21 时代 `new Identifier(...)` 已被 `Identifier.of(...)` 取代；26.2 用 `Identifier.fromNamespaceAndPath(ns, path)`（`26.3` 又改名为 `withNamespaceAndPath` ✅，说明**第二个参数系列在 26.2/26.3 之间变过**，26.2 请用 `fromNamespaceAndPath`）。

#### 3.1.2 其他高频 Yarn → 官方名（本项目命中）

`World`→`Level`、`ItemGroup`→`CreativeModeTab`、`Text`→`Component`、`Formatting`→`ChatFormatting`、`AbstractBlock.Settings`→`BlockBehaviour.Properties`、`MinecraftClient`→`Minecraft`、`ScreenHandler`→`AbstractContainerMenu`、`StatusEffect`→`MobEffect`、`Registries`→`BuiltInRegistries`（内置注册表）、`RegistryKeys`→`Registries`（键常量）+ `ResourceKey`（键类型）、`Registries.STATUS_EFFECT`→`BuiltInRegistries.MOB_EFFECT`。

官方包在 26.2 中确认存在（Fabric API 字节码统计）✅：`net.minecraft.core.component.DataComponents`、`net.minecraft.world.level.block.state.BlockBehaviour`、`net.minecraft.world.effect.MobEffect`（12 个类）、`net.minecraft.core.registries.Registries`（30）、`net.minecraft.core.registries.BuiltInRegistries`（50）、`net.minecraft.network.chat.Component`（78）、`net.minecraft.world.item.ItemStack`（93）、`ChatFormatting`（14）、`com/mojang/blaze3d`（40）。

#### 3.1.3 自动迁移工具（**这是本阶段的关键**）

| 工具                          | 说明                                                                                                                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Loom 的 `migrateMappings` 任务 | 半自动；**不支持 Kotlin**                                                                                                                            |
| **Ravel**（IntelliJ IDEA 插件） | GUI 对话框，**支持 Kotlin**，复杂项目表现更好；Fabric API 自身就是用 Ravel 完成映射迁移的（fabric PR \#4960）                                                               |
| Fabric 官方 IntelliJ 迁移映射     | 26.1 博客指向 [Fabric Docs · 26.1 fabric-api](https://docs.fabricmc.net/develop/porting/26.1/fabric-api) ⚠️（本机网络到 `docs.fabricmc.net` 被阻断，见 §8）** |

> Fabric 官方警告：**两种工具都不完美，仍需人工复核，尤其是 Mixin** ✅。这正是 §4 强调"映射迁移单独成一个提交"的原因。

**Mixin 是重命名最危险的地方**：每个 `@Inject(method="...")` 的目标描述符、每个被引用的类名都要重新指向。本项目 3 个 Mixin（[richards-whimsy-mod.mixins.json](../../../src/main/resources/richards-whimsy-mod.mixins.json)）里，`RichardsWhimsyModMixin` 是空实现（可直接删除），`BHR_Compost4CropMixin` 注入 `CropBlock` 的 `canPlantOnTop`/`getAvailableMoisture`（Yarn 名 + 签名双重依赖），`BHR_GemBlessingAmethystMixin` 需逐一核对。

## 4. 路线建议

### 4.1 结论：**不要一次性从 1.20.4 跳到 26.2**

直接跳会同时叠加 6 波独立的破坏性变更（1.20.5 组件化、1.21 改名、1.21.2 HolderSet、1.21.5 渲染 + 物品子类移除、1.21.9 渲染队列、26.1 去混淆），排错时无法归因。正确做法是**把"映射迁移"从"API 升级"里拆出来，作为独立的一次提交**。

**关键洞察**：映射迁移是**可自动化**的（Loom `migrateMappings` / Ravel），且与玩法 API 变化**正交**。因此：

```
1.20.4  ──(Yarn 时代完成所有 vanilla API 升级)──►  1.21.11（最后一个混淆版本）
                                                      │
                                        映射迁移（独立提交，人工复核 Mixin）
                                                      ▼
                                                   26.1 ──► 26.2
```

**推荐路线（二选一）**：

|     | 路线甲：完整阶梯                                                           | 路线乙：压缩阶梯（**推荐**）                                                            |
| --- | ------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| 路径  | 1.20.4 → 1.20.6 → 1.21.1 → 1.21.5 → 1.21.11 → [映射迁移] → 26.1 → 26.2 | 1.20.4 → **1.21.11**（在 Yarn 下把最难的 vanilla API 变化一次做完）→ [映射迁移] → 26.1 → 26.2 |
| 优点  | 每一步报错可归因，可借相邻版本的教程/工具                                              | 工作量约为甲的一半；映射迁移工具面向相邻版本，一次做完最省事                                              |
| 缺点  | 工作量约 2–3 倍                                                         | 1.20.4→1.21.11 一段内仍会堆叠数次变更                                                  |
| 适合  | 想每步都能进游戏验证                                                         | 内容型小模组（本项目 4.6k 行）                                                          |

> 无论走哪条路，**1.21.11 及之前的任何 1.20.4 产物都不能直接在 26.1+ 运行**，必须重新编译 ✅。

| 3 | Mixin `compatibilityLevel` 的目标值 | 读 26.2 示例模组的 `*.mixins.json` |
| 4 | `fabricApi { configureDataGeneration() }` 在新 plugin id 下是否仍有效 | 实测；必要时改用 `loom { runs { datagen } }` |
| 5 | 26.2 的 `pack_format` 数值 | [Misode 版本变更表](https://misode.github.io/versions/?id=26.2&tab=changelog) / 客户端 `version.json` |
| 6 | 官方名下的常量持有类名：`FoodProperties`、`StatusEffects`、`ToolMaterial` 等（不出现在 Fabric API 字节码中，不能据此判定存在与否） | [mcsrc.dev](https://mcsrc.dev) 查 26.2 源码 |
| 7 | `EntityAttributes.GENERIC_MAX_HEALTH`→`Attributes.MAX_HEALTH`、`Operation.ADDITION`→`ADD_VALUE` 等字段改名 | 同上 |
| 8 | 26.2 后处理着色器（`shaders/post/*.json`）格式 | 同上 |
| 9 | 数据包单数目录在 26.2 的确切形态 | 26.2 `runDatagen` 产出对照 |
| 10 | 26.2 vs 26.3 之间"模组可在 `DataGeneratorEntrypoint` 注册可重载注册表"的落地版本 | Fabric API changelog |
