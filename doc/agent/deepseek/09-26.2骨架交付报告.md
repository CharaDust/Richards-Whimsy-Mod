### 0.3 关于「注册时机」的一个重要设计决定

**注册一律发生在 `OnInit()` 里，不放在静态字段初始化中。** 原因是 26.2 的
`Item.Properties.setId(...)` 会**立刻触发 `BuiltInRegistries.ITEM` 的 `bootstrap()`**：

- 若物品在静态字段里就 `setId` + 注册，等于在 `onInitialize()` 之前把物品注册表自举起来；
- 那时候方块的静态注册**还没有发生**，一旦以后有「物品在构造时需要查方块」的用法就会踩坑。

方块本身没有这个问题（`Block` 自带 `id()`，会把 key 存起来而不自举），
但为了两类保持一致、便于阅读，**方块也改成在 `OnInit()` 里构造并注册**。

### 0.10 本轮三个问题的实测答案

#### Q1：datagen 产出的 lang 只含当前已注册的键 —— 这是硬限制

datagen **只能为「已注册」的方块/物品生成键**，因为它拿不到尚未注册的东西。
所以：现在 DEV 只有 3 个注册项，datagen 产出就只有 4 个键（3 项 + 物品栏标题）。
手上那份手写 lang 的 81 个键里，绝大部分属于**还没重制**的方块/物品 ——
那些键在对应方块被重制出来之前，datagen 生成不了。

→ 结论：**datagen 生成语言文件可行，但要等各模块陆续重制完才会逐块补齐**。
现在删掉手写 lang 会让未重制的内容失去翻译，所以先并行放着。

#### Q2：方块键与方块物品键**必须各写一份**（已实测，26.2）

在 datagen 里把真实的翻译键打出来过：

```
block  descriptionId = block.richards-whimsy-mod.dev_block_normal
item   descriptionId = item.richards-whimsy-mod.dev_item_normal
```

**这两个键是分开的，不能合并。** 原因：方块物品的翻译键取自它
**自己的物品 id**，不会回退到方块的键（26.2 的 `BlockItem` 不覆写
`getDescriptionId`，键由 `Item` 按自身 id 推导）。

**但「两处维护、文字重复」是可以避免的**：在 lang provider 里让物品键**复用方块的译本**，
文字只写一处：

```java
// 方块物品显示成「和方块同名」
builder.add(DEV_ItemsOther.DEV_ITEM_NORMAL,
            DEV_BlocksOther.DEV_BLOCK_NORMAL.getDescriptionId());
```

想给方块物品单独起名时再写自己的字符串。这一招我在 `DEV_LangProviderZh` 里留了注释示例。

#### Q3：模型/方块状态也能 datagen，但在客户端侧

26.2 的模型生成器 `net.minecraft.client.data.models.BlockModelGenerators`
**已不在 common jar 里**（只在 client jar），Fabric 侧对应
`net.fabricmc.fabric.api.client.datagen.v1.provider.FabricModelProvider`，
方法是 `generateBlockStateModels` / `generateItemModels`。

它属于**客户端数据生成**：需要数据生成运行在客户端环境
（`DataGenerationSettings#client = true`），而我们现在的 `runDatagen`
是按服务端环境跑的。**本轮未实测**（改这个要动数据生成运行配置，
且我无法起客户端验证），因此模型/方块状态**暂时仍手写**。

→ 现状：**lang + 战利品表已 datagen；模型/方块状态待评估**。

### 2.3 旧代码如何处置

**没有删除、没有改名、没有移动**——它们仍在原路径，只是**不参与编译**。

做法是在 `build.gradle` 里排除了 10 个具体子包：

```groovy
exclude 'com/rcdmake/whimsy/block/**'   // 以及 datagen / function / item / itemGroup /
exclude 'com/rcdmake/whimsy/datagen/**' // mixin / recipe / registry / screen / tag，共 10 条
```

> **踩过的坑**：一开始写的是 `exclude 'com/rcdmake/whimsy/**'`，想让整棵树都不编译，
> 结果 `compileJava` 报 `NO-SOURCE`——**Gradle 的 `exclude` 优先于 `include`**，
> 后面再加 `include` 也救不回来。所以排除项必须是「具体子包」，
> 新代码放在 `skeleton/` 与三个根入口类，结构上永远不会被命中。

**为什么没按原计划搬到 `src/main/javaref/`**：本会话的 shell 子进程沙箱只允许写
工作区根目录与 `toolchain-check/`，`src/` 下一律拒绝**创建目录**，
因此 `Move-Item` / `robocopy` / `git mv` 全部不可用。IDEA 关不关都不影响 ——
这不是文件占用，是沙箱权限。实测证据：

| 操作 | 结果 |
| --- | --- |
| `robocopy . src\main\javaref …` | ❌ `ERROR 5 (0x5) Creating Destination Directory … Access is denied` |
| `Move-Item` 到 `src/…` | ❌ 对路径的访问被拒绝 |
| `git mv` | ❌ 无法创建 `.git/index.lock`，Permission denied |
| 对照组：`robocopy . toolchain-check …` | ✅ 成功 |
| 智能体自身的文件写入工具写 `src/main/javaref/` | ✅ 能建目录（但 shell 随后仍写不进去） |

> 顺带否掉一个理论方案：虽然文件工具能建目录，但 87 个文件要走 87 次「读原文 + 写副本」
> 的往返，既慢又有内容损坏风险（这些旧文件带中文注释与 GBK 遗留）。
> 批量移动交给有完整文件系统权限的进程（你的终端 / IDEA）才稳妥。

**替代方案（已经把活干到只剩一步）**：`toolchain-check\migrate-to-javaref.ps1`
+ `toolchain-check\build.gradle.post-move`，你在普通终端跑一条命令即可。
详见 08 号文档 §4 方案 B。脚本的 dry-run 已实测识别出正确的 **87 个文件 / 10 个包**。

`build.gradle.post-move`（迁移后版本，即删掉 10 行 exclude）已单独实测：
曾临时装到项目上跑 `clean build runDatagen` —— 在**旧文件尚未搬走**的前提下它
按预期失败（100 个旧 API 报错），这正好证明了两件事：该配置本身正确，
且必须在搬完文件之后才能替换。

| 资源标识符 | `net.minecraft.util.Identifier` | **`net.minecraft.resources.Identifier`**（简单名不变，**不是** `ResourceLocation`） |

| 音效组 | `BlockSoundGroup` | **`SoundType`**（`net.minecraft.world.level.block`） |

### 3.2 注册（1.21.2+ 起的强制形态）

```java
// 物品：key 必须写进 Properties.setId，漏写 → 运行时 NullPointerException: Item id not set
ResourceKey<Item> key = ResourceKey.create(BuiltInRegistries.ITEM.key(), id(path));
Item item = new Item(new Item.Properties().setId(key));
Registry.register(BuiltInRegistries.ITEM, key, item);

// 方块：同理，走 BlockBehaviour.Properties#setId
// 方块还要单独注册一个 BlockItem，物品栏里才拿得到
```

- `Registry.register` 有三个重载：`(Registry, String, T)` / `(Registry, Identifier, T)` / `(Registry, ResourceKey, T)`。
- **`ResourceKey.create` 里现在也可以用 `Registries.ITEM`**（它就是 `ResourceKey<Registry<Item>>`），
  与 `BuiltInRegistries.ITEM.key()` 等价。

### 3.3 🔴 本轮的「最大意外发现」：原版创造标签页键变成 private

```java
CreativeModeTabs.INGREDIENTS   // ← 26.2 里是 private static！外部访问 = 编译不过
```

实测 26.2 的 `CreativeModeTabs` 里 **`INGREDIENTS` / `BUILDING_BLOCKS` /
`TOOLS_AND_UTILITIES` / `COMBAT` / …全部是 `private static ResourceKey`**，
类里只留了 `bootstrap` / `tabs` / `allTabs` / `searchTab` 等少数 public 方法。

**影响**：以往「把自己的物品塞进原版标签页」的标准写法在 26.2 **直接失效**。
两条出路：

1. **注册自己的标签页**（骨架采用的做法，见 `ModCreativeTabs`）；
2. 自己重建原版键：
   `ResourceKey.create(Registries.CREATIVE_MODE_TAB, Identifier.withDefaultNamespace("building_blocks"))`

### 3.5 其它已核验的改名 / 新要求

- `BlockBehaviour.Properties#copyOf(block)` → **`ofFullCopy(block)`**（另有 `ofLegacyCopy`）。

## 4. 下一轮怎么继续（重制流程建议）

1. **先 `genSources`**（08 号文档 §3）。没有反编译源码，IDE 里点不进方法体，重制会很痛苦。
2. **按 wiki 逐条重制**，每条产出一个类放进 `skeleton/` 之外的正式包
   （建议沿用旧包名 `block/ClassXxx`，方便与旧代码对照）。
   用 `ModSkeleton.registerBlockWithItem` / `registerItem` 作模板。
3. **每重制一条，就从 `build.gradle` 的排除列表里去掉对应包**，编译即验。
4. **旧的 `*_ClientRenderInit` 不要迁移，直接删。**
   26.1 起渲染层自动判定，而 wiki 里这批方块的渲染描述（「依据纹理像素点存在性透明 /
   依据纹理 Alpha 通道透明」）恰好与新版自动行为一致 —— 03 号文档的推测已被证实。
5. **优先级**：方块 → 物品 → 状态效果 → 方块实体 → 容器/配方 → 数据生成 → 渲染。
   渲染与 `DEV_OverlayRenderer` 放最后（26.2 有 Vulkan 后端与 Feature Rendering 重写）。

## 5. 本轮踩到的坑（全部已修，记录备查）

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | `compileJava NO-SOURCE`，构建「成功」但什么都没编译 | **Gradle `exclude` 优先于 `include`**，`exclude 'com/rcdmake/whimsy/**'` 把新代码也排除了 | 改成 10 条具体子包排除 |
| 2 | jar 里是 2024 年的旧 class | 上一轮 1.20.4 的 `build/` 残留 + `NO-SOURCE` 导致 jar 直接打包旧产物 | `clean` 后复查 jar 内容 |
| 3 | `gradlew.bat` 报「找不到 java」 | wrapper 先检查 `JAVA_HOME`，`gradle.properties` 的 `org.gradle.java.home` 还没机会生效 | wrapper 里加 JDK 自动适配 |
| 4 | 批处理脚本报奇怪的「不是内部或外部命令」 | `.bat` 里写了中文注释，`cmd.exe` 按 ANSI 代码页读取导致解析错乱 | 批处理文件改为纯 ASCII |
| 5 | `Could not find a fabric.mod.json file in the data source set` | `createSourceSet = true` 时 Loom 要求 datagen 源集自带元数据 | 改回 `createSourceSet = false` |
| 6 | `Property has implicit dependency ... :runDatagen ... :sourcesJar` | Loom 默认把 datagen 产出写进 `src/main/generated`，而 `:sourcesJar` 扫描整个 `src/main`；Gradle 9 直接中断构建 | ① `outputDirectory` 移出 `src/main`；② 本项目刻意不开 `withSourcesJar()` |
| 7 | `Entry .cache/... is a duplicate` | datagen 的 `.cache/` 被当成资源重复拷贝 | 交给 Loom 自己的排除规则，**不要手动 `srcDir`**（手动挂会立刻产生 json 重复） |
| 8 | IDEA 项目 SDK 指向不存在的 `17` | 历史配置 | 见 08 号文档 §1 |

| # | 事项 | 说明 |
