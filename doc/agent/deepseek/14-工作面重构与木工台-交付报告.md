# 工作面重构与木工台 · 交付报告

> 日期：2026-12
> 范围：工作面（Working Surface）内核抽取、木工台落地、加固平台、工作面线材料、产物族、原版配方投影与下发
> 相关文档：[工作面](../wiki/Misc/工作面.md)、[配方](../wiki/Misc/配方.md)、
> [木工台](../wiki/Blocks/ClassBlockHeadsRebon/BHR_WoodworkBench.md)、[加固平台](../wiki/Blocks/ClassBlockHeadsRebon/BHR_ReinforcedPlatform.md)

## 一、一句话

把原先「制作台 / 简易篝火」两份几乎重复的实现合并成一套**工作面内核**，在其上落地**木工台**；
并打通「**原版配方运行时投影 + 下发**」这条链路，让木工台 L2 能直接做原版按树种拆开的门 / 栅栏 / 告示牌等。

## 二、做了什么

### 1. 工作面内核（`com.rcdmake.whimsy.surface`）

原先 `BHR_Workbench*` 与 `BHR_Campfire*` 各自一套 ~1600 行几乎相同的实现（实体 / 菜单 / 界面）。
现在合并为：

| 文件 | 职责 |
| --- | --- |
| `WorkingSurfaceSpec` | 一台工作面的全部差异（id / 底图 / 等级上限 / 燃料档位 / 面板偏移） |
| `WorkingSurfaceBlock` | 等级状态、放置取等级、掉落带等级、右键开界面 |
| `WorkingSurfaceEntity` | 配方选择 / 倍率 / 进度 / 燃料 / 结果栏 / 暂存原料 / 存档 |
| `WorkingSurfaceMenu` | 槽位下标按 spec 推导 |
| `WorkingSurfaceScreen` | 一份绘制覆盖三台 |
| `FuelOption` | 燃料档（含标签兜底） |
| `WorkingSurfaceStateSync` | 方块外观钩子（篝火的 `lit`） |

三台现各自只是薄声明：`BHR_WorkBench` / `BHR_WoodworkBench` / `BHR_Campfire`。

### 2. 进度模型统一成「时间差 + 区间结算」

```
虚拟时间 = (暂停中 ? 暂停起点 : min(now, 燃料燃尽刻)) − 累计暂停
进度     = clamp(虚拟时间 − 本份开始刻, 0, 本份时长)
```

- 没人在看时方块完全不 tick，区块卸载不影响进度；
- 燃料台的「缺燃料暂停」用区间表达，补燃料时一次性累加 —— 所以**燃料台也不再需要 ticker**；
- 篝火只保留随机刻做心跳（结算 + 刷 `lit`），打开界面时立即结算。

### 3. 木工台（`bhr_woodwork_bench`）

1~3 级、无燃料、复用 `workbench.png` 底图；L1 共 11 条本地配方（含新增「果木栅栏」），
L2 由原版投影供料；升级 L2 = 木头×5 / 180s（专家 木头×10 + 铁锭×1）。

### 4. 产物族（family）

一条配方覆盖全部树种：`{"result":{"family":"door","from":0}}` + `bhr_family/<族>.json`
（`source_suffix` / `target_suffix` / `default` / `special` / `map`，按后缀约定自动解析，加树种不用改码）。

### 5. 原版配方投影与下发（方案 B）

- **服务端** `VanillaRecipeProjector`：扫 `data/*/recipe/**.json`，按 `surface/vanilla_recipes.json`
  的三道筛（形状 / 产物白名单 / 材料白名单）过滤，翻成**愚者配方 JSON**；
- **两端** `VanillaRecipeIndex` 注入同一张配方表；客户端靠 `SurfaceRecipesPayload`（Fabric
  `clientboundPlay`）在**打开界面时**接收一次全量；
- 远端配方在引擎眼里就是普通愚者配方，**选配方 / 看成本 / 开始制作 / 专家回退全部复用现成代码**；
- `/reload` 后服务端清缓存（`END_DATA_PACK_RELOAD`），客户端下次开界面拿到新的一份。

选择状态改为 **id 权威**（`selectedId`）+ 下标仅用于高亮，避免重载换批后指错配方。

### 6. 专家模式回退

同一产物：有专家版用专家版，缺了退回普通版。规则集中在 `BHR_FoolRecipes.visibleFor/nextUpgradeFor`，
实体与界面共用。

## 四、过程中修掉的坑

1. **`Recipe` 没有 `getIngredients()`**（26.2 改为 `RecipeDisplay`/`SlotDisplay`）——投影因此改读数据包 JSON。
2. **规则表路径必须带 `.json`**：`ResourceManager#getResource` 收的是完整文件名，第一版漏了扩展名，
   结果「投影 0 条」且不报错（只有 DEBUG 才看得出来）。
3. **木棍不在任何木质标签里**：栅栏 / 栅栏门 / 告示牌第一次投影全灭，材料白名单因此支持直接写物品 id。
4. **展示架重复**：原版展示架是「6 去皮原木 → 6」，与本地 `l2_shelf` 撞车，改由原版投影统一供给后从本地移出。
5. **专家版 shelf 产物没跟着改**：普通版已改成物品展示框，专家版还写着 `oak_shelf`，
   会在专家模式多出一条幽灵条目 —— 已统一。
6. **工作台底面用了侧面贴图**：已改为与顶面同图（和制作台一致）。

## 五、已知限制 / 后续

- `/reload` 后**正开着**的工作面界面不刷新，需关闭重开；
- 愚者配方与原版投影配方都不是原版 `Recipe`，**JEI 看不到**（适配待做；接法是 `jei_mod_plugin`
  读本模组数据，不需要网络）；
- 原版投影一次性全量下发（81 条、几十 KB）；将来有工作面订阅上千条时再加分页；
- 铜锭 / 锡锭贴图未入库（借原版贴图占位）；四件材料的正式获取途径待裁缝台 / 冶炼线；
- 木工台本体配方按约定暂缓（所有工作面加完后统一编写）；
- 楼梯 / 台阶 / 按钮 / 压力板属于以后的工作面，未纳入本台。
