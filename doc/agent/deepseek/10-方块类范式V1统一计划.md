# 10 · 方块类范式 V1 统一计划（按模块 · 改动量由低到高）

- 编写：DeepSeek 智能体（deepseek-flash）· 本轮
- **依据**：范式定稿 [`doc/wiki/example/blockv1.md`](../../wiki/example/blockv1.md) + 样板 [`ParadigmBlockV1.java`](../../../src/main/java/com/rcdmake/whimsy/block/paradigm/ParadigmBlockV1.java)
- **前提**：范式**讨论已结束**（V1 定稿），本计划只做**统一（归一）**；统一是行为零变化的重构，不做功能改动
- **执行方式**：一个阶段 = 一个可测试单元 = 你进游戏测一轮；测过再开下一阶段

## 0. 不变量（每个阶段都必须守住）

| 不许动 | 具体所指 |
| --- | --- |
| 注册名 | `ModRegister.registerBlockWithItem("<id>", ...)` 与 `ModRegister.blockKey("<id>")` 里的字符串 |
| 属性数值与开关 | `strength` / `friction` / `destroyTime` / `pushReaction` / `igniteOdds`+`burnOdds` / `INSIDE_DRAG` / `BREAK_DELAY_TICKS` / `FRICTION` 等 |
| 覆写点的语义 | 方法体照抄，只允许**换位置**，不允许删改任何一行行为 |
| 资源与数据制品 | blockstates / models / items / textures / lang 的**最终内容**（`runDatagen` 写入必须为 0） |
| datagen 声明 | `BlockStateGenerator.collectAll()` / `ItemModelGenerator.ITEM_MODEL_OVERRIDES` 的条目 |
| 主类调用顺序 | `RichardsWhimsyMod.onInitialize()` 里的 `OnInit()` 次序（阶段 0 只动注释） |

## 1. 每个阶段的固定动作

1. 读一遍 `blockv1.md` 对应层；只改本阶段范围内的文件；
2. 我做：`gradlew build` 通过 + `gradlew runDatagen`（**写入必须 0 个**：纯重构不该改任何产物）；
3. 我做自查：`git diff` 的**非注释增删必须成对相等**（同一批行换位置）；出现只加不减/只减不加的非注释行 → 有行为改动，停下复核；
4. 我给你：本阶段改动文件清单 + 差异摘要；
5. 你在 IDEA 提交一个还原点（我这边的 `.git` 写入被沙箱拒绝，提交必须由你做）；
6. **你进游戏按 §本阶段「游戏内测试清单」逐条测** → 有丢功能立刻回退该提交。

## 2. 阶段排序（改动量由低到高）

| 阶段 | 范围 | 改动量 | 依据 |
| --- | --- | --- | --- |
| **0** | 跨模块公共小件（语言助手 / 物品栏写法） | 最低（~8 个文件，每处几行） | 三份重复的 `addBlockAndItem` 与三种物品栏写法先收口，后面阶段直接复用 |
| **1** | **WI 模块**（6 类 + 语言 + 物品栏） | 低（6 类换位 + 2 类补对照表） | 6 个类都已有属性工厂，只需「工厂↔构造器」换位 + 补契约栏 |
| **2** | **RDT 模块**（6 类 + 语言 + 物品栏） | 中低（同 WI + 3 处特殊信息归位） | 多出：家族继承（层 6）、可燃性登记（层 12）、Mixin 指针（层 M）、多块类（3 个方块） |
| **3** | **DEV 模块**（7 类 + 语言 + 物品栏） | 最高（**6 个类要新增属性工厂**） | 5 个 `DEV_State*` + `DEV_BlocksOther` 把 Properties 内联在 `OnInit()` 里，属结构改动而非位置移动 |
| **4**（可选） | 全量一致性复核 | 0 代码 | 过一遍 19 类的范式 checklist，出「一致性检查表」 |

> 排序理由：阶段 1/2 是「搬位置 + 补注释」（diff 里非注释增删成对相等），阶段 3 会**新增方法**（只加不减），风险最高，所以压到最后 —— 前面的阶段能帮你先把「测试手感」练出来。
