## 1.（必做）项目 SDK 与语言级别 → JDK 25

当前 `.idea/misc.xml` 里项目 JDK 名叫 `17`，**这台机器上并不存在这个 JDK**，
所以 IDEA 现在必然是满屏飘红。改法：

1. `File` → `Project Structure…`（快捷键 `Ctrl+Alt+Shift+S`）
2. 左侧选 `Project`
3. **SDK** 下拉 → 若列表里没有 25，点 `Add SDK` → `JDK…`，
   选择目录：`C:\Program Files\JetBrains\IntelliJ IDEA 2026.2.3\jbr`
   （也可以直接选 `Download JDK…` 让 IDEA 装一个独立的 Temurin 25，但没必要）
4. **Language level** 选 `25 - ...`
5. `Apply` → `OK`

> 若下拉里已经有 `jbr-25` 之类的条目（IDEA 通常会自动登记自带 JBR），直接选它即可。

## 2.（必做）Gradle 的 JVM → Java 25

Gradle 自身必须跑在 Java 25 上（Loom 1.18 要求 Gradle ≥ 8.14，26.2 的 toolchain 要 25）。

1. `File` → `Settings…`（`Ctrl+Alt+S`）
2. `Build, Execution, Deployment` → `Build Tools` → `Gradle`
3. **Gradle JVM** → 选第 1 节那个 25 的 SDK
4. 勾选 **Use Gradle from: `gradle-wrapper.properties` file**（默认就是这个，确认一下）
5. `Apply` → `OK`，然后点工具条上的 **Reload All Gradle Projects**（大象图标）

> 项目 `gradle.properties` 里已经写了 `org.gradle.java.home=…\jbr`，
> 即使忘了这步，命令行构建也能自己找对 JDK；但**让 IDEA 也一致**才不会出现
> 「命令行能过、IDE 里飘红」的分裂状态。

## 3.（必做）生成 Minecraft 反编译源码 —— 你在 IDE 里查 API 的前提

这是**最关键的一步**，直接决定你后续重制时能不能「点进去看签名」：

1. 打开右侧 `Gradle` 工具窗
2. 展开 `richards-whimsy-mod` → `Tasks` → `fabric` → 双击 **`genSources`**
3. 首次约 3~10 分钟（Vineflower 反编译整个客户端）
4. 完成后，在代码里 `Ctrl+B`（跳到声明）就能看到 Minecraft 26.2 的真实源码

> 26.1 起 Minecraft 不再混淆，但**仍然需要反编译**才能看源码。没有这一步，
> 你在 IDE 里只能看到方法名而看不到实现，重制时的效率会差一个量级。

## 4.（强烈建议）把旧代码标成「排除」

现有 90 个 1.20.4 时代的 `.java` 文件仍在 `src/main/java/com/rcdmake/whimsy/` 下。
`build.gradle` 已经在编译层面排除了它们（十个具体子包），**构建不受影响**，
但 IDEA 仍会把它们当源码索引 → 满屏 `Cannot resolve symbol 'Registries'` 之类的红字。

**这不影响构建，但会淹没真正的错误。** 处理方式二选一：

### 方案 A（临时，保持文件原位）—— 用 IDEA 的目录排除

1. 在项目视图里右键 `src/main/java/com/rcdmake/whimsy/block` → `Mark Directory as` → `Excluded`
2. 对 `datagen` / `function` / `item` / `itemGroup` / `mixin` / `recipe` / `registry` / `screen` / `tag` 重复
   （共 10 个，正好对应 `build.gradle` 里的 10 行 `exclude`）
3. 排除后这些目录在 IDEA 里变橙黄色，不再参与索引与错误提示

> 缺点：`Excluded` 会连**跳转与查找**一起关掉，对照旧代码时略有不便。

### 方案 B（推荐，你原先选的目标形态）—— 移到 `src/main/javaref/`

**已备好一键脚本**：`toolchain-check\migrate-to-javaref.ps1`
（本会话的智能体沙箱无法写 `src/` 下的目录，所以这一步必须由你在普通终端执行）

```powershell
# 1. 先干跑，只看清单、不动文件
powershell -NoProfile -ExecutionPolicy Bypass -File .\toolchain-check\migrate-to-javaref.ps1 -DryRun

# 2. 确认后执行（87 个文件，10 个包）
powershell -NoProfile -ExecutionPolicy Bypass -File .\toolchain-check\migrate-to-javaref.ps1
```

脚本会做四件事：

1. 把 10 个旧子包（87 个 `.java`）搬到 `src/main/javaref/com/rcdmake/whimsy/`，
   保留原有目录结构；**三个入口类与 `skeleton/` 原地不动**（它们是新骨架）；
2. 仓库有 `.git` 时用 `git mv`，保留重命名历史（否则退回 `Move-Item`）；
3. 删掉搬空的旧目录（`itemGroup/` 里的 `#.exp` 不是 `.java`，会保留该目录）；
4. 把 `build.gradle` 换成 `toolchain-check\build.gradle.post-move`
   —— 即删掉那 10 行 `exclude`，原文件备份为 `build.gradle.pre-move.bak`。

**脚本执行完还要在 IDEA 里做两步**：

- 右键 `src/main/javaref` → `Mark Directory as` → `Excluded`
- 点 **Reload All Gradle Projects**（大象图标）

> 这个脚本的 dry-run 已实测：正确识别 **87 个文件 / 10 个包**。
> 真跑那段（文件移动）无法在本会话验证，因为沙箱禁止写 `src/`；
> 但 `build.gradle.post-move` 本身已实测通过 `clean build runDatagen`。

**若不想用脚本**，就用 IDEA 的图形界面：

1. 项目视图里选中 `src/main/java/com/rcdmake/whimsy` 下的 10 个旧子包
   （`block`、`datagen`、`function`、`item`、`itemGroup`、`mixin`、`recipe`、
   `registry`、`screen`、`tag`）
2. 右键 → `Refactor` → `Move…` → 目标 `src/main/javaref/com/rcdmake/whimsy`
3. 右键 `src/main/javaref` → `Mark Directory as` → `Excluded`
4. 手动删掉 `build.gradle` 里那 10 行 `exclude`

> 用 IDEA 移动的好处：`.idea` 里的路径映射会同步更新，且 IDE 会提示引用冲突。

**为什么现在不改扩展名为 `.javaref`？**
按你的决定保留 `.java`。原因是 IDEA 只把 `.java` 当 Java 解析，改成自定义扩展名后
语法高亮、跳转、结构视图全部失效，变成纯文本，对照阅读会明显变差。
`Excluded` 已经足以让它们不产生编译/诊断错误。

## 5.（建议）运行配置

Gradle 已经生成好了三个 Run Configuration，在右上角下拉里应该能直接看到：

| 名称 | 用途 | 首次注意 |
| --- | --- | --- |
| `runClient` | 起开发客户端 | 首次要下载游戏资源（`downloadAssets`），几分钟 |
| `runServer` | 起开发服务端 | 首次要在 `run/` 下建 `eula.txt` 填 `eula=true` |
| `runDatagen` | 跑数据生成 | 产出在 `build/generated/datagen/`，再 `build` 才会进 jar |

若下拉里没有，点 `Edit Configurations…` → `+` → `Gradle`，在 `Tasks` 填对应任务名，
`Gradle project` 选本项目即可。

**正确用法**（`build.gradle` 里已注明）：先 `runDatagen`，再 `build`。

## 6. 注意事项

1. **不要用 IDEA 自带的「Build Project」代替 Gradle 构建。**
   本项目依赖 Loom 的配置阶段产出（`fabric.mod.json` 的 `${version}` 展开、
   datagen 产出挂接等），必须走 Gradle 任务。
2. **`gradlew.bat` 被改过（加了本机 JDK 自动适配）。** 目的是让没有任何
   `JAVA_HOME` 的机器也能构建。它只在 `JAVA_HOME` 未设置且该路径存在时才生效，
   换机器不受影响。**注意该文件必须保持纯 ASCII** —— `cmd.exe` 按 ANSI 代码页读 `.bat`，
   写中文注释会让脚本解析错乱（这个坑本轮已经踩过一次）。
3. **改了 `fabric.mod.json` 后要重新 `processResources`**（即重跑 `build`），
   否则 jar 里还是旧元数据。
4. **依赖缓存里已有 26.2 全部所需内容**，断网也能构建；但如果清了
   `%USERPROFILE%\.gradle`，首次重建需要联网（约 0.4 GB）。
