# 02 · 升级前置条件缺口分析

- 项目：Richard's Whimsy Mod
- 分析日期：2026-10-06（Asia/Hong_Kong）
- 目标：Minecraft 26.2 Fabric
- 范围：只分析迁移前必须具备的环境、版本、基线和资料；本次不修改源码与版本配置。

## 结论

当前不能直接开始大规模迁移。最先需要解决的是 Gradle Wrapper 的可运行性和 26.2 工具链锁定；源码迁移本身可以在这两个条件具备后展开。

| P0 | 26.2 的版本组合尚未写入并验证 | 当前仍为 Loom 1.6-SNAPSHOT、Loader 0.15.9、Fabric API 0.96.11+1.20.4、Yarn 1.20.4+build.3 | 依赖解析与映射 API 都仍是旧版本 |

## 已具备但需要接通的条件

- IntelliJ IDEA 自带 JBR 25.0.4，路径为 `C:\Program Files\JetBrains\IntelliJ IDEA 2026.2.3\jbr`；该目录同时包含 `java.exe` 和 `javac.exe`。
- Gradle 用户目录存在，项目也有 `.gradle/8.7`、Loom 缓存等目录；这说明本机曾产生过 Gradle/项目缓存，但不代表当前依赖完整或可构建。
- Gradle Wrapper 文件存在，当前指向 `gradle-8.7-bin.zip`。
- 仓库已有 Fabric 模组入口、客户端入口、数据生成入口和 Mixin 配置；迁移不需要重新搭建空项目。

## 26.2 迁移前需要锁定的版本条件

根据 Fabric 26.2 示例和官方开发页面，本项目在实际改配置前需要逐项确认并记录最终版本：

- JDK 25；当前 IntelliJ JBR 25.0.4 可作为候选运行时。
- Minecraft 26.2。
- Fabric Loader 至少 0.19.5；开发页面与示例分支的推荐值可能不同，最终以实际解析成功的组合为准。
- Fabric Loom 1.18-SNAPSHOT 或当时官方 26.2 示例采用的兼容版本。
- Fabric API 的 26.2 对应版本；不能继续使用 `0.96.11+1.20.4`。
- 与 26.2 相匹配的 mappings。26.2 的 mappings 选择、命名方式和可用版本必须通过依赖解析验证，不应沿用 `1.20.4+build.3`。
- 与上述组合匹配的 Gradle Wrapper 版本；当前 8.7 不能预先假定兼容。

## 迁移前必须准备的项目资料

1. 一份可复现的旧版本构建结果：至少包含 `build`、数据生成和客户端启动是否成功的记录。
2. 一份注册表清单：方块、物品、物品栏、状态效果、方块实体、ScreenHandler、配方类型和网络内容。
3. 一份资源清单：模型、blockstate、语言、配方、战利品表、标签、着色器和 `pack.mcmeta`。
4. 一份 Mixin 清单：每个注入目标、方法签名、注入点和运行环境。目标版本变化后必须逐个复核，不能只做文本替换。
5. 一份功能验收清单：进入世界、获取物品、放置方块、打开界面、使用状态效果、触发自定义配方、客户端渲染和专用服务器启动。
6. 明确的版本控制策略：建议先保存当前 1.20.4 可恢复状态，再在独立迁移分支上修改版本配置。

## 推荐顺序

1. 让命令行或 IntelliJ 使用 JBR 25.0.4，并解决 Gradle Wrapper 下载/缓存问题。
2. 先恢复 1.20.4 的 `build` 基线；如果旧版也无法构建，先记录并隔离原始问题。
3. 建立一个独立的 26.2 Gradle 配置提交，只改工具链与元数据，不同时批量改 Java 源码。
4. 通过依赖解析确认 Loader、Loom、Fabric API、mappings 和 Gradle 的实际组合。
5. 以最小模块开始迁移，再按注册、数据组件、数据生成、界面、渲染、Mixin 和资源顺序扩展。
6. 每完成一个功能面，运行对应的构建、数据生成或游戏验收，并把结果继续记录在 `doc/agent/gpt/`。
